## 1. 一句话与和 v1 的关系

v2 在 v1 日计划之上，先给 agent 一条稳定的命令行接口，再给条目可选的日期/时钟提示，最后加一个自然语言窗口：用户说话，背后用用户自己配置的脚本叫 agent 代操作。

v1 仍然成立，v2 是加法，不是换产品：

| v1 已冻 | v2 怎么对待 |
| --- | --- |
| D1 主场景仍是写今天 | 人继续用网页写今天；CLI / 窗口是代操作，不改主节奏 |
| D2 给人用的是本机网页 | 终端给 agent，不给人做日常 TUI |
| D3 库存 → 今日抽取 | To Do 仍是未排期库存；日期属性不得擅自变成第二套排期 |
| D5 不做小时表 | 时钟是条目上的可选提示，不是 06:00–23:00 格子 |
| D6 / D9 日界 | 未完成 Plan 回 To Do，未完成 Errands 作废；时间属性不改变日界 |
| D7 本机、不同步 | 仍只在这台电脑；不接云账号、不内置厂商 agent |
| D11 同一条可跨日抽 | 稳定 id 继续是跨日身份 |
| D13 过去只读 | CLI 与窗口都不能成为改历史的后门 |
| D14 可排到未来某天 | 继续用现有「排到某天」。To Do 上的目标日 **不是** 排期，到期也不会自动变成当天 Plan |

界面上的三个桶（现状，v2 沿用这个叫法）：

| UI | 含义 | 对应 v1 |
| --- | --- | --- |
| Plan | 当天正经待办 | 某一天的正经待办列表 |
| Errands | 当天差事 | 零碎差事 |
| To Do | 未排期库存 | 库存 |

## 2. 给谁用

- **人：** 仍在本机网页里写今天、翻过去、管 To Do。
- **Agent：** 用 CLI 代人读写同一份计划。v2c 的窗口只是人把自然语言交给自己选的 agent；真正改计划的仍是 CLI。

第一用户没变：同时有课业、实验室、竞赛和多个代码项目的本人。v2 要多赢的是：人可以口述，agent 可以按稳定命令改计划，而不必先会点网页。

---

## 3. 建议分期

CLI 是窗口的前置。没有稳定命令行，窗口只能内嵌某一家 agent，或让模型直接猜网页，二者都不接受。

| 分期 | 做什么 | 依赖 |
| --- | --- | --- |
| **v2a CLI** | agent 专用稳定命令行：覆盖现有领域命令，JSON 输出，稳定 id，遵守封印/日界；另加 `context` | 无。先做 |
| **v2b 可选时间** | To Do 的日期；Plan 的起始和/或结束时钟；输入框 + 滑动列表。**不是**小时表 | 不依赖窗口。建议紧跟 v2a，好让随后的脚本也能读写时间字段 |
| **v2c 自然语言窗口 + 用户定义 agent 分组** | 人叙述后发送；背后跑用户配置的脚本；可自加启动器并挑选 | **必须先有 v2a**。不内置 Codex / Claude SDK |

v2b 与 v2c 无硬依赖。建议顺序仍是 a → b → c，避免窗口上线后还要回头补时间字段。

`serve` / `backup` 保留。v2a 是在它们之外增加领域命令，不是改掉现有两条。

## 4. Agent 窗口怎么驱动（明确建议）

用户原话问：窗口背后是否应该用脚本（例如 `codex prompt`）让 agent 代操作。

**建议：用「用户配置的脚本」驱动。产品不内置 Codex / Claude 或任何厂商 SDK。**

理由（产品，不是架构）：

1. 用户已经在用外部 agent，举例就是命令行脚本。
2. 喜欢哪家 agent 会变；内置 SDK 会把产品和某一家的登录、版本绑死。
3. 「分组」按用户原话是为了挑选喜欢的 agent，不是课业/实验室/竞赛那种项目分组。

因此：

- **分组 = 用户自己加的启动器**：一个显示名 + 一条命令模板。
- 发送 = 跑选中的启动器，把用户原话和当天上下文交给它。
- Agent 只通过 v2a CLI 改计划，不直接操作网页、不走未文档化的内部接口。
- 产品可以给一两条示例模板（例如 `codex prompt …`），但默认不捆绑、不替用户安装任何 agent。

已拍板：分组 = 用户自己加的启动器（名字 + 命令模板）。产品不内置厂商 SDK。示例模板是否预置仍可后置，默认列表可以从空开始。

## 5. v2a：给 agent 的 CLI

CLI 是 **agent 专用稳定接口**，不是给人每天点的终端 UI。人继续用网页（D1、D2）。

### 5.1 必须做到

1. **覆盖现有领域命令。** 网页今天能做的读写，agent 用命令也能做，规则相同。不必另发明一套「agent 专用业务」。
2. **JSON 输出。** 成功与失败都要能被脚本解析。稳定字段名、稳定 id。给人看的纯文本若有，也只是附加，不是契约。
3. **稳定 id。** Plan 条目用任务 id，Errands 用差事 id；跨日是同一条任务 id（D11）。Agent 不得靠标题模糊匹配当主路径。
4. **遵守封印与日界。** 每条命令与网页同一套「今天」、同一套结转：过去日只读；未完成 Plan 回 To Do；未完成 Errands 作废；已封印永不解封。CLI 不是改历史的后门。
5. **不必先打开网页。** Agent 跑命令时，不要求浏览器开着。
6. **另加 `context`。** 把「今天的 Plan + Errands」和「To Do」打成一份 JSON，方便脚本一次性喂给 agent。这是给窗口/脚本的入口，不是新的业务对象。

不提供「手动封印 / 解封 / 改今天是哪一天」给 agent。结转发生在命令路径里，与网页相同。

### 5.2 必须覆盖的现有能力

读：

- 打开某一天（含今天、未来、过去只读）
- 列出 To Do
- 读元信息（今天的日期、时区、库存数量等，与网页同一「今天」）
- 读月历占位（哪些天有条目）
- `context`（今天 + To Do 的一份打包）

写（仅可写日：今天与未来）：

- 在某天写下 Plan 条目；写入 To Do
- 把 To Do 排到某天；把某天的 Plan 条目移回 To Do；改排到另一可写日
- 勾选 / 取消勾选 Plan 与 Errands
- 在某天写下 / 改名 / 删除 Errands
- 改名 / 删除任务（删除规则与 v1 相同：有封印历史则不能删）
- 重排当天 Plan；重排当天 Errands

内部测试用的封印原语不是用户命令，也不进 agent CLI。

### 5.3 `context` 建议范围

建议一份里只含：

- 服务器认定的今天、是否可写
- 今天的 Plan（id、标题、勾选、排序；v2b 之后含时钟）
- 今天的 Errands（id、标题、状态、排序；若 Errands 有时钟则一并带上）
- 全部 To Do（id、标题、创建时间；v2b 之后含日期）

建议 **不** 塞进 `context` 的：完整历史、任意过去日全文、未来所有已排期日。Agent 若要看某一天，再调打开那天的命令。

待确认：`context` 要不要附带「已排到未来、因此不在 To Do 里的任务」一份短列表，以免 agent 误以为那件事丢了。

### 5.4 对 agent 的产品契约

- 非法写过去日 → 失败，计划不变。
- id 不存在、状态冲突 → 结构化失败，不静默改别的条目。
- 同一条未完成任务仍然不能同时排到两天。
- 命令用的「今天」是产品日历日（上海民用日），不是 agent 机器上的系统时区日。

## 6. v2b：可选时间属性（不是小时表）

v1 明确不做 06:00–23:00 小时时间块（D5）。v2b **仍然不做小时表**。不出现右栏时间轴、不把一天切成格子、不按小时占位。

时间是条目上的 **可选属性**：没有时间的条目与 v1 完全一样。

### 6.1 Plan：时钟

Plan 上每条正经待办可以有：

- **开始时钟**（几点开始）
- **结束时钟**（几点前完成）

二者独立，**不必同时存在**。用户可以只说「九点开始」，或只说「五点前做完」，或两个都填，或不填。

输入：**输入框打字 + 滑动列表选择**。两种都要能落到同一个时钟值。控件长什么样交给设计，需求只冻「能打、能滑，不是去小时表上拖一块」。

**已拍板（V2-D6）：** 时钟跟当天那次出现走。没做完回 To Do 时，时钟留在那天历史上；再次抽到另一天，重新选。过去日只读展示当时写下的时钟。不自动按时间重排，不改日界，不产生逾期状态。

设计层默认（未另作产品决策，实现按此）：

- 只限该条所在那天的时刻，不跨午夜。
- 开始与结束都填时，结束不得早于开始。
- 滑动列表步长 5 分钟；输入框可打 `9:00` / `21:30` 这类时刻。

### 6.2 To Do：日期

To Do 上每条可以有一个可选日期。**不是** Plan 上那种时钟。

**已拍板：目标日。** 任务仍留在 To Do，**不会**自动变成那天的 Plan。只表示「和哪一天相关 / 希望哪天做」。要进某一天的 Plan，仍须抽到那天（现有 D14 排期）。

这与现有「排到某天」正交，不是同一操作。

**已拍板（V2-D5）：** 到了或过了目标日，**不会**自动进当天 Plan；To Do 上要有应用内提醒，能看出到期/过期。不做系统通知、闹钟、锁屏横幅。

抽到某一天的 Plan 时：目标日仍留在任务上；回到 To Do 时还在。当天 Plan 不靠目标日把条目拉进来。

### 6.3 Errands 的时钟

**已拍板：要，且可选，与 Plan 同一套** 起始/结束时钟（输入框 + 滑动列表）。Errands 仍只属于某一天、不进 To Do、没做完当天作废（D9）。时钟不让差事复活，也不让它跨日。不给 Errands 再加一份 To Do 式目标日。

## 7. v2c：自然语言窗口与用户定义的 agent 分组

人在一个窗口里用自然语言叙述「今天要怎样」，发送后，产品不自己理解、不自己排程，只启动用户选中的脚本，由外部 agent 经 CLI 代操作。

### 7.1 窗口要能做的事

1. 输入自然语言，发送。
2. 发送前能挑选一个 agent 分组（启动器）。
3. 用户能自己添加、改名、修改命令模板、删除分组。
4. 跑的时候把用户原话和 `context` 交给脚本（具体注入方式待确认，见 §11）。
5. 能看到脚本在跑、成功、失败；失败时能看到脚本吐出的内容。**发送后立刻跑**（V2-D7），不先预览。Agent 经 CLI 写出的就是真的；窗口不另做整单回滚。
6. 窗口嵌在现有本机网页里（V2-D8），不是独立小窗。

### 7.2 分组（启动器）

一条分组至少有：

- **名字**（人用来选，例如 `Codex`、`Claude`）
- **命令模板**（用户自己写，例如调用 `codex prompt` 或任何别的可执行文件）

建议还可以有：是否为默认启动器。待确认。

不是：

- 不是课业 / 实验室 / 竞赛 / 代码项目的任务分组（那仍是 v1 后置项）
- 不是产品内置的 agent 账号体系
- 不是提示词市场、不是自动选模型

### 7.3 和 CLI 的关系

窗口不能绕过 CLI。没有 v2a 就没有 v2c。网页上的人操作与 agent 经 CLI 的操作，落在同一份计划、同一套规则上。

## 8. 明确非目标

v1 的非目标，除「终端」被 **收窄放开** 为「agent CLI」外，其余继续成立。v2 额外明确：

- **小时时间块 / 电子课程表 / 把一天画成 06:00–23:00 格子**
- **内置 Codex、Claude 或任何厂商 SDK、登录、API 密钥管理**
- **系统通知、闹钟、锁屏提醒、到点横幅**
- **外部日历同步**（Google / Apple / CalDAV 等）
- **产品自己做 AI 自动排程**（不替用户决定今天做什么；只把话交给用户选的脚本）
- **给人用的 TUI / 交互式终端日视图**（CLI 输出给脚本解析，不是日常界面）
- **改写已封印的过去某一天**（CLI、窗口、脚本都不行）
- **手机端、多设备同步、云账号、多人协作**
- **项目树、标签体系、优先级系统、习惯打卡**
- **历史全文搜索**
- **把 To Do 目标日当成「排到某天」或到期自动进 Plan**
- **启动器替用户安装或升级外部 agent**

## 9. 额外方向（少而准）

下列作为本稿建议，便于拍板时少走弯路。不是已冻实现。

1. **CLI 与网页共用同一套规则库。** 禁止 CLI 自己算「今天」、自己结转、自己解释封印。人在网页勾的和 agent 在命令行勾的，必须是同一条身份、同一次日界。
2. **过去日在 CLI 里也只读。** 与 D13 对齐。脚本不能靠命令行补勾昨天。
3. **脚本工作目录与环境要有一份最小约定。** 否则用户写启动器时无从下手。建议至少约定：在哪类目录里启动、如何找到同一份数据、用户原话和 `context` JSON 怎么交给命令模板。占位符名字待确认。
4. **不做系统通知，不接外部日历。** 时钟和 To Do 日期都是计划内部的提示，到期不会弹 OS 通知，也不会写进 Calendar.app。
5. **启动器配置算用户本机设置。** 建议纳入备份能找回来的范围，或在备份说明里写清「计划数据」和「启动器列表」各在哪。待确认二者是否绑在一起。
6. **窗口不是聊天产品。** 不要求多轮会话历史、不要求产品记住上次 agent 说了什么。若外部脚本自己有会话，那是脚本的事。

## 10. 成功标准

- Agent 不打开浏览器，也能列出今天的 Plan / Errands 和 To Do，并用稳定 id 勾选、新增、排期、移回库存。
- 对过去日的写入一律失败；日界后第二天仍是干净的（D6、D9）。
- 同一条正经待办经 CLI 跨日再抽，仍是同一个 id（D11）。
- 人可以给 Plan 条目只填开始、只填结束、两个都填、或都不填；界面上仍是一份清单，不是小时表。
- 人可以自加至少一个启动器，选中后发送一句自然语言，看到脚本被启动；产品没有内置任何一家 agent SDK。
- 关掉窗口或脚本，计划数据仍在这台电脑上。
