# 规划迭代：当前重点与可审阅草案

2026-10-03。用户同意按建议开始迭代。首个切片落实规划首页的当前重点、下一步落地和草案字段对照；后续继续阶段逐步细化、范围约束、轻量回顾与暂停后续接。

## 当前重点

- 规划首页默认「当前重点」，可切换「目标地图」。由用户选择目标，没有自动推荐排序或默认替用户选中的目标；按选择顺序展示。
- 卡片显示目标、大致时间、当前阶段、阶段成果和实际下一步。候选行动、待办、今天及未来日期清楚区分；未设下一步时可就地选择已有行动，也可打开路线添加行动。
- 加入今天／待办复用领域命令；已落地的下一步通过 schedule-next 携带原任务 ID 与原安排，安排到未来的事项明确显示「改到今天」。请求携带版本及恢复代次，失败刷新实际状态，快速重复点击被本次操作锁保护。
- 暂停、结束及移除的重点不显示在当前视图；选择记录保留，目标恢复后重新出现。完成任务后由既有领域操作清除下一步，不自动选新行动或完成阶段。
- 重点选择属于本机视图偏好，不改变目标、Task 或草案，不进入数据库备份。网页版使用 localStorage 并同步其他同源页面；桌面使用按数据目录区分的原生 UserDefaults，注入 WebKit，重启及端口变化不影响选择。没有强制的 2–3 个数量限制，最多保存 100 个有效 ID。
- 全局草案编辑时使用原有地图与路线预览，避免将未保存的目标视为可执行任务；保存或放弃后返回原视图。

## 草案字段对照

- 在原有变更明细中按目标、阶段、行动展示，明确原来／调整后。由服务端比较草案基线与已校验文档生成；不使用模型自报内容。
- 覆盖名称、备注、大致时间、支持目标、当前阶段、下一步、阶段成果、阶段状态、行动归属及顺序。引用显示目标／阶段／行动名称；单目标草案引用外部父目标时从领域数据读取名称。序号按用户习惯从 1 开始显示。
- 新增前为「无」，移除后为「移除」，清空字段为「未填写」。中文、多行和长文本保留，按文本渲染，不执行 HTML。目标移除明确说明已有任务与完成记录保留。
- `PlanningDraft.changes[]` 增加可选 `fields[]`：`field, label, before, after`，值为字符串或 null。既有 kind/id/goalId/type/title 及变更统计语义保持；只在读取时生成，无数据库迁移。旧服务未提供 fields 时仍能展示对象变更。
- 保存、撤销、放弃、回执和正式任务保护保持领域层语义；本轮不支持逐项接受、不改变助手修改范围的校验，也不引入自动排程。
