# 长期目标的数据兼容性

长期目标和阶段使用独立的 `008_goals.sql` 迁移。已有待办、日期安排和历史条目不会被重写：旧任务的 `goal_id`、`phase_id` 与历史目标快照字段在升级后均为 `NULL`。

从包含此检查的版本开始，打开数据库时会先核对 `schema_migrations` 是否为本应用已知版本的连续前缀。遇到未知、跳号或未来版本会直接拒绝打开；在此之前不会执行迁移或写入元数据。已发布的 v7 及更早版本没有这项保护，不能用于打开已升级到 v8 的数据库；需要降级时，应恢复升级前自动创建的迁移备份。

备份恢复仍先在临时副本中校验完整性、表结构和时区，再升级并替换当前数据。验证覆盖：

- v7 备份恢复并升级后，原任务和每日条目的目标字段保持为空；
- 包含目标、阶段、关联任务和每日关联快照的 v8 备份恢复后，字段值完整保留；
- 带未知未来迁移记录的数据库拒绝打开且原有数据不变。

相关自动化测试：`tests/persistence/test_goals_migration.py`、`tests/test_goals_recovery.py`。
