# Now 需求冻结稿

状态：已冻结（2026-08-31）。  
决策依据见 [v3-now-decisions.md](v3-now-decisions.md)。v1、v2 继续成立；冲突处以本文件对 Agent 入口的收敛为准。

## 1. 目标

让 Local Planner 从“每天手写一张计划”扩展为“能可靠承接长期固定节奏，并在每天第一次规划时集中做选择”。Now 同时交付定期事项、每日规划流程和 Agent 改动回执，三者共用领域规则。

## 2. 定期事项

用户可以创建每天或每周多星期的 Plan / Errand 系列，并查看进行中、已暂停、已停止的系列。

必须满足：

1. 每个命中日最多生成一期，重复打开、重启或补结转不得重复。
2. 应用离线跨日后，必须先补出该日实例，再按既有日界规则封印。
3. 每期有独立 id；完成、改名、改时钟只影响本期。
4. 模板修改、暂停、恢复、停止只影响尚未生成的未来日期。
5. 历史继续只读；系列账本不能成为改写封印日的后门。
6. 日视图和 To Do 可标出实例的系列来源。
7. 系列只有进入“已停止”终态后才能删除；删除只隐藏系列，不删除任何已经生成的事项、账本或历史来源。

定期管理页提供创建、编辑、暂停、恢复、停止，以及删除已停止系列。进行中或已暂停系列不能删除，必须先停止。创建 Errand 时显示无系统提醒说明。

## 3. 每日规划

服务端每天仅持久化“尚未规划 / 已就绪”。当天首次进入 Today 时，尚未规划则主动展示规划工作表；用户可关闭，Today 留下轻量入口。

工作表依序显示：

1. 今天已经生成的定期 Plan / Errands；
2. 昨天未完成并回到 To Do 的 Plan；
3. 目标日为今天或更早的 To Do；
4. 其余 To Do；
5. 未来七天已有排期与定期投影的只读摘要。

同一任务只出现在一个候选分组，优先级为“昨日回库”高于“到期 / 逾期”，再高于“其他 To Do”。候选不会自动进入今天。只有服务器认定的上海今天能标为已就绪。

## 4. Agent 与回执

Agent 的主要使用时机是每日首次规划：规划工作表保留“让助手整理”入口。同时，顶部导航常驻“计划助手”按钮，允许用户从任意页面按需展开同一个 Agent 侧边栏。两个入口共享面板、运行状态与回执；发送时附带当前页面上下文（今天、To Do 或指定日期），并立即执行用户选择的启动器，通过 CLI 改同一数据库。

结果必须区分：

- 成功且有改动：按类型列出结构化变化；
- 成功但无改动：明确说明没有发现计划改动；
- 失败且可能已有部分改动：不得虚报回滚，刷新当前计划并提示检查；
- stdout/stderr：仅作技术输出。

本期不做聊天历史、自动运行 Agent、自动排程、系统提醒、撤销整次 Agent 执行。

## 5. 验收

- 每天与每周多星期规则均可创建并正确生成。
- 离线跨日至少三天后，Plan 欠账与 Errand 作废历史符合既有语义。
- 暂停区间不补发；停止不可恢复；已生成实例不被模板编辑修改。
- 进行中或已暂停系列删除返回冲突；已停止系列删除后不再出现在管理列表和 Agent 上下文，历史实例仍保留来源。
- 未规划的 Today 能进入规划流程，关闭不误标，确认后当天不再主动弹出。
- 候选分组、去重、未来七日摘要由 API 提供，前端不复制日界或重复算法。
- Agent 面板默认关闭，普通页面只常驻轻量入口；每日规划入口与全局入口打开同一面板，执行结果能给出可信的结构化回执与失败提示。
- 安装后运行 `local-todo` 或 `local-todo open`：服务未启动时在后台启动并等到健康后打开网页，已经启动时直接复用；`local-todo serve` 仍以前台方式运行。
- 桌面和移动端均可操作；状态、来源和错误不只靠颜色表达。
