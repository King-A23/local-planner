# Luna 真实 Agent 验证

2026-09-28。用户授权在独立窗口使用 Luna 进行真实任务测试，发现偏差后优化，确认后推送。

## 环境与隔离

- 从打包的 macOS 应用复制独立测试实例，使用独立 bundle ID、数据目录和工作目录。
- 沿用用户已有的 `Codex · GPT-6 Luna · medium` 配置：`gpt-6-luna`、medium、fast；仅将工作目录指向测试目录。
- 全部自然语言任务从测试窗口的助手输入框发送，实际调用模型及应用内置 CLI，没有使用测试替身。
- 只使用人工生成的测试事项。真实数据库不作为 Agent 上下文；开始与结束通过只读 SQLite 逻辑内容 SHA-256 比对，结果一致。
- 原始执行输出、请求参数、上下文快照、进程暂停及数据库校验证据保存在本机忽略目录 `build/luna-real-qa/`，不提交模型会话日志。

## 场景与结果

本轮共 11 次真实模型运行，包括 1 次主动暂停后终止的旧指令。下表合并同场景的首次执行与复测；不把进程退出成功直接当作任务成功，而是核对实际数据、ID、完成状态、时间、备注及完整顺序。

| 场景 | 核对结果 |
| --- | --- |
| 同一句话改期、追加备注、未完成项置顶 | 首次发现完成项槽位移动；最终使用事务内 `move`，保留正确槽位、其他未完成项相对顺序、原 ID、09:00–10:00 和原备注；追加内容仅出现一次 |
| 未来已完成事项恢复 | 从完整未来上下文定位原 ID，恢复未完成、修改备注，保留原开始时间 |
| 待办直接完成 | 从待办移到今天的完成记录，回执包含加入今天和完成 |
| 恢复按时间排序 | 持久排序模式正确切回自动 |
| 仅截止时刻 | 「下午四点半前」保存为 endClock 16:30，startClock 为空 |
| 同名事项 | 待办和明天各有一条「整理周报」，助手询问目标，没有猜测或写入；修复后询问直接显示在回执 |
| 领域边界 | 零碎事项跨日、完成项直接改期、昨天写入均明确说明不可执行，没有删除重建或取消完成绕过 |
| 待办页面新增及复杂备注 | 未指定日期时写入待办；两行备注中的 `$20`、双引号、反引号按原文保存 |
| 待办页面创建定期计划 | 每周五、从今天生效、09:00 开始、结束为空；没有误建为一次性待办 |
| 真实暂停与继续 | 本机 Codex 进程状态为停止态，暂停期间计时与测试数据库不变、API 可用；同一个 run 继续后完成原指令 |
| 暂停后修改指令 | 旧 run 以 stopped 结束且无写入，新 run 读取当前数据完成替换后的指令；旧标题没有被创建 |
| 未来日期页默认位置 | 在 2026-09-29 页面未指定日期的新增写入当天，14:00 开始且无结束时间 |
| 移回待办及零碎事项相对排序 | 保留原事项 ID、备注；未来日不再有该计划；`day errand move --after` 正确调整当天零碎事项 |

## 修复

1. 新增 `day todo move` / `day errand move`，支持 `--first`、`--last`、`--before`、`--after`。读取最新顺序与写入在同一事务内完成，只移动同日同列未完成项，保留完成项槽位。
2. 复测发现数据库保存顺序可能与界面自动时间排序不同。将展示顺序提取到领域层共用，JSON 展示与相对移动使用同一排序规则；回归用例刻意构造两种顺序不同的情形。
3. 预置提示词明确先改期／完成／新增，最后排序；单项移动优先使用新接口，全量排序必须重新读取。执行中出现过一次 shell 引号错误且自行修正，进一步补充含空格路径、原文特殊字符和多行备注的调用指引；最终复测未再出现该错误。
4. 最终模型回复直接显示，澄清与限制不再藏在执行详情。无数据改动但有回复时显示「助手已回复」，数据库差异回执仍单独保留。设置使用说明同步这一行为。

## 自动检查与边界

- 298 项 Python 测试通过，包括两类相对移动、含完成项槽位、保存顺序与展示顺序不同、改期后重排、失效参照、完成项／跨日／历史拒写、失败原子性。
- 18 项前端测试、TypeScript/Vite 构建、macOS 打包及签名校验通过。
- 这是所列场景的真实验证，不是任意自然语言都能正确执行的保证。仍以数据库实际改动回执为准，歧义需要补全原指令；暂停不会撤销已经发出的远端请求。
- 测试结束退出独立应用并核实其后端、Agent 进程及监听端口已清理；用户原有应用与服务保持运行。
